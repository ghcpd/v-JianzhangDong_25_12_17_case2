Overview

This workspace contains a small Flask application (input.py) and a vulnerable original copy (input_backup.py). I performed a security audit and applied fixes. The repository now includes automated tests and scripts to validate the vulnerabilities and the fixes.

Files generated

- input_backup.py: Original vulnerable source (backup).
- input.py: Hardened and patched source.
- report.json: Structured report of discovered vulnerabilities and fixes.
- requirements.txt: Python dependencies.
- Dockerfile: Container image to run the app.
- setup.sh: Setup helper to prepare a virtualenv, install dependencies and create a sample DB and config.
- run_test.sh: Linux/macOS test orchestrator that runs the vulnerable app and the patched app and verifies behavior.
- run_test.bat: Windows test script (best-effort).
- auto_test.py: Automatic test runner (detects environment and runs tests). It writes logs to logs/test_run.log.
- tests/test_vulnerabilities.py: The test suite used to probe vulnerabilities in each app instance.
- logs/test_run.log: Test run logs (generated by auto_test.py).
- report.json: JSON report with full details of each fix.

Setup

1. Create a virtual environment and install dependencies (Linux/macOS):
   ./setup.sh

2. Ensure the following environment variables are set before running the patched app in production:
   - PAYMENT_TOKEN
   - INTERNAL_AUTH
   - ADMIN_API_KEY
   - (optional) CONFIG_DIR

Running tests

Linux/macOS:

- Quick (single script): ./run_test.sh
  This script will start the vulnerable app, run vulnerability checks (expect vulnerable), stop it, then start the patched app and verify that vulnerabilities are mitigated.

- Automatic with logs: python auto_test.py
  This runs the same sequence and writes detailed timestamped logs to logs/test_run.log and prints TEST PASSED or TEST FAILED.

Windows:

- Use run_test.bat (best-effort): run_test.bat
  Note: Running background processes and killing them on Windows is best-effort in this script.

Interpreting logs

- logs/test_run.log contains per-app test output with ISO timestamps. Each run ends with a final line: TEST PASSED or TEST FAILED.

Notes

- Do NOT put real secrets in environment variables or the repository. Use a secrets manager in production.
- The patched app enforces an API key (X-API-KEY) on sensitive endpoints; set ADMIN_API_KEY appropriately when running the app.
- The test suite is intentionally simple and intended for demonstration and local verification only.
