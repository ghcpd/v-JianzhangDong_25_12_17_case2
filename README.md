# Project: Secure `input.py` audit and fixes

## Overview
This workspace contains a security audit and a hardened version of `input.py`.

Files generated:
- `input_backup.py`: original, unmodified file (backup)
- `input.py`: the hardened implementation with fixes for identified vulnerabilities
- `report.json`: structured vulnerability report with fixes and explanations
- `tests/test_security.py`: pytest suite that verifies secure behaviors
- `run_test.sh` / `run_test.bat`: platform test runners (use `TARGET_FILE` env var)
- `auto_test.py`: automatic test runner that executes tests for both `input_backup.py` and `input.py` and writes logs to `logs/test_run.log`
- `requirements.txt`, `Dockerfile`, `setup.sh`: environment setup files
- `logs/test_run.log`: generated by `auto_test.py` when tests run


## Setup (Linux/macOS)
1. Create a virtual environment and install dependencies:
   ```bash
   ./setup.sh
   source .venv/bin/activate
   ```

2. Run tests for a specific file (example for patched file):
   ```bash
   export TARGET_FILE=./input.py
   ./run_test.sh
   ```

## Setup (Windows)
1. Install requirements into your environment (replace with venv usage if desired):
   ```powershell
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   ```

2. Run tests for a specific file (example for patched file):
   ```powershell
   set TARGET_FILE=.\input.py
   run_test.bat
   ```

## Automatic testing
To run automatic tests for both backup and patched file and produce logs:
```bash
python auto_test.py
```
Logs are written to `logs/test_run.log`. Each test run includes timestamps and a final `TEST PASSED` or `TEST FAILED` line.

## Notes
- Secrets (API keys) are read from environment variables. Configure them before deploying.
- The patched code validates URLs, sanitizes inputs, and avoids shell calls to mitigate command injection and SSRF risks.
